# Rural Mobility Energy Model

Modelling and analysis of road transport energy demand, decarbonization levers and multi-objective optimization strategies in rural areas, using the Cuadrilla de Gorbeialdea (Álava) as a case study.

The study builds a digital energy model of regional mobility from open data and answers six chained research questions:

| ID | Question | Models |
|---|---|---|
| Q1 | What is the actual hourly, segment-level energy demand, broken down by trip origin? | M1, M2 |
| Q2 | Which technical, operational and demand-management levers apply? | M7 |
| Q3 | What net saving results from shifting travellers to public transport? | M3, M4 |
| Q4 | How much petroleum use is avoided by fuel substitution? | M5 |
| Q5 | How much energy does speed management save, and at what time cost? | M6 |
| Q6 | Which combination of Q3, Q4 and Q5 is optimal? | M7 |

The full methodology is in `main.tex`.

## Repository layout

```
main.tex             Manuscript (human-authored, XeLaTeX)
log.tex              Work log (AUTO-GENERATED, never edit)
generate_log.py      Rebuilds log.tex from the Git history
config/study.yaml    Study parameters (single source of truth)
data/                raw and interim data are gitignored; see data/README.md
src/gorbeialdea/     One module per model (m1 to m7) plus common utilities
scripts/             Numbered entry points
notebooks/           Exploration only, never the source of results
tests/               Unit tests
results/             Generated tables and data files
figures/             Generated figures used by main.tex
docs/                Data requests and design decisions
.github/workflows/   Continuous integration (log and PDF build)
```

Results used in the manuscript are generated by code into `results/` and `figures/`; numbers are not typed by hand.

## Getting started

```powershell
git clone https://github.com/aritz-ezkerro/rural-mobility-energy-model.git
cd rural-mobility-energy-model

python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
pip install -e .
```

To compile the manuscript locally, open the folder in Visual Studio Code with the LaTeX Workshop extension and a MiKTeX distribution. The workspace recipe runs XeLaTeX twice on save.

## Working cycle

1. `git pull` before starting, to receive the `log.tex` updated by the workflow.
2. Edit and preview locally.
3. Commit and sync at the end of the session.

On every push to `main`, GitHub Actions regenerates `log.tex`, commits it as the bot, compiles `main.tex` with XeLaTeX and uploads `main.pdf` as a workflow artifact.

## Commit message convention

The work log is built from commit messages, so they must follow this format:

```
[HH:MM] Concise English title of the session

- First task completed
- Second task completed
```

- The session end time is taken from the commit timestamp (Europe/Madrid).
- `[HH:MM]` is the session start time. For multi-day sessions use `[YYYY-MM-DD--HH:MM]`.
- Body lines starting with `- ` become bullet points in the log.
- Never edit `log.tex` by hand. To change its layout, edit `generate_log.py` or the `\logentry` macro in `main.tex`.
